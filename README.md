# tokenizer-vitis — MicroBlaze firmware for the FPGA tokenizer

The **software half** of the FPGA BERT WordPiece tokenizer: the MicroBlaze application that
runs *inside* the FPGA SoC, accepts text over TCP, streams it through the hardware tokenizer
core via **AXI DMA**, and returns the `bert-base-uncased` token IDs to the client.

This is one of three repositories:

| Repo | What it holds |
|------|---------------|
| **[tokenizer-vivado](https://github.com/talsh123/tokenizer-vivado)** | Vivado project + custom RTL + testbenches (the hardware tokenizer) |
| **tokenizer-vitis** (this repo) | MicroBlaze firmware: lwIP TCP server, AXI DMA driver, RTL8211E PHY patches |
| **[tokenizer-csr](https://github.com/talsh123/tokenizer-csr)** | Python that compiles the BERT vocab → the `.mem` CSR trie images |

> Full project write-up, results (100 % / 66-66 exact match, ~285× energy efficiency), and
> the defense deck are in **[tokenizer-vivado](https://github.com/talsh123/tokenizer-vivado)**.

---

## What it does

The MicroBlaze soft-processor runs an **lwIP TCP server** (echo-style, port **7**). For each
line of text a client sends, the firmware:

1. DMAs the bytes into the tokenizer core over **AXI4-Stream** (S2MM/MM2S, no per-byte CPU work),
2. reads the produced 16-bit token IDs back out, and
3. sends the IDs to the client.

It uses **AXI4-Lite** for control/status and as a fallback datapath. The board takes its IP by
**DHCP**, falling back to `192.168.1.10`. A UART console at **115200** carries boot/debug logs.

## The RTL8211E PHY patch (important)

The Nexys Video's **RTL8211E** PHY needs two BSP files edited to link at gigabit:
`xadapter.c` and `xaxiemacif_physpeed.c` (under
`platform/.../bsp/libsrc/lwip220/src/lwip-2.2.0/contrib/ports/xilinx/netif/`).

**Re-reading the `.xsa` or regenerating the BSP wipes those edits.** The durable fix lives in
[`lwip_echo_server/src/phy_patch/`](lwip_echo_server/src/phy_patch/): the patched files are
stored as `*.golden` and re-applied by a script. After any BSP regeneration, run:

```powershell
powershell -ExecutionPolicy Bypass -File lwip_echo_server/src/phy_patch/apply_phy_patch.ps1
```

then rebuild the app. Without this, Ethernet won't link.

## Building & flashing

1. Point the platform at the current `design_1_wrapper.xsa`
   (**Update Hardware Specification**) and rebuild the platform/BSP.
2. **Re-apply the PHY patch** (above) if the BSP regenerated.
3. Build the `lwip_echo_server` app, program the FPGA, and run it.

Built with **Vitis 2025.2**. Only source is tracked here — the compiled BSP, bitstreams, and
CMake/Ninja build trees are regenerated by the Vitis **Build** action (see `.gitignore`).
